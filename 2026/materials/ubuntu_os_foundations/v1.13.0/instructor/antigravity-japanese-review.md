## 1. 校閲の基本方針と共通変更事項

1. **文体の統一**: 全体を客観的で論理的な「である」調（常体）に統一。曖昧な体言止めや不自然な直訳文を、日本の大学IT教育で自然に読める教科書表現へ改善。
2. **専門用語の標準化**:
   - `file` → ファイル
   - `directory` → ディレクトリ
   - `user` → ユーザー
   - `group` → グループ
   - `command` → コマンド
   - `process` → プロセス
   - `service` → サービス
   - `socket` → ソケット
   - `port` → ポート
   - `log` → ログ
   - `package` → パッケージ
   - `kernel` → カーネル
   - `shell` → シェル
   - `path` → パス
   - `resource` → リソース
   - `interface` → インターフェース
   - `permission` → 原則として「アクセス権」に統一（8進数モードやビットの文脈では「パーミッション」を併用）
   - 「低い層」→「低レイヤー」
   - `primary group` → 主グループ、`supplementary group` → 補助グループ
3. **英語の維持**:
   - `Linux`, `Ubuntu`, `Unix`, `systemd`, `systemctl`, `SSH`, `SCP`, `HTTP`, `TCP`, `IP`, `GUI`, `CLI`, `PID`, `UID`, `GID`, `AWS CloudShell`, `Session Manager` 等の固有名詞・標準規格・識別子・コマンド名は完全に維持。
4. **多言語翻訳（英語・ウズベク語・ロシア語）への配慮**:
   - 省略されがちな主語を補い、動作主体（OS、カーネル、シェル、プロセス、ユーザー）を明確化。
   - 文化依存の比喩表現を廃し、技術的因果関係が明白に伝わる構文に整理。
